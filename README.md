# LabAssetManager (实验室设备资产管理系统)

基于 C++ (Qt6) 开发的实验室设备资产管理平台。实现设备信息录入、编辑、删除、检索；设备借用、归还登记；设备维保记录管理；设备状态统计；支持导出资产清单。

## 👨‍💻 1. 开发环境要求（基准环境与兼容策略）

由于大家本地的机器配置不同，我们**不强求环境的绝对统一**，但为了确保代码能互相拉取编译、链接不报错，请所有人遵守以下**基准与兼容策略**：

### 📌 基准环境（用于最终测试与验收）

- **操作系统**：Windows 10 / 11 (64-bit)
- **IDE**：Visual Studio 2022
- **构建工具**：CMake (>= 3.16)
- **Qt 版本**：**Qt 6.0.1** (msvc2019_64 套件)

### 🤝 环境不一致的妥协方案（务必遵守）

1. **必须使用 MSVC 编译器**：无论你装的是 VS2017、2019 还是 2022，Qt 必须使用 **MSVC 版本**（如 `msvc2017_64`、`msvc2019_64`），**绝对禁止**有人使用 MinGW 版本（会导致无法链接）。
2. **Qt 版本“就低不就高”**：如果组内 Qt 版本有差异（比如 6.0、6.2、6.5），写代码时**只能使用低版本也支持的 API**。如果你用了高版本的特有 API，导致队友编译报错，你需要负责重写。
3. **工具集“向下兼容”**：如果有人使用 VS2022 (v143)，有人用 VS2019 (v142)，VS2022 的工具集是向下兼容的。遇到链接错误时，由使用**最新版本 VS 的同学负责最终的集成链接**。
4. **各扫门前雪（CMake 路径配置）**：每个人在自己本地的 CMake 配置中设置自己的 Qt 路径。拉取代码后，如提示找不到 Qt，请自行修改本地的 `CMAKE_PREFIX_PATH`（不要把个人的绝对路径提交到 Git 的 `CMakeLists.txt` 中）。

> **💡 强烈建议**：如果你实在搞不定自己本地的环境（比如一直报 DLL 找不到、报错 LNK2038），请在群里求助，或者使用远程桌面借用队友的电脑跑一遍。

## 🛠️ 2. 如何构建项目

1. 克隆本仓库到本地。
2. 打开 Visual Studio，选择 **“打开本地文件夹”**，选中项目根目录。
3. 在 VS 顶部的配置下拉框中，选择 **`x64-Debug`**。
4. 等待 VS 自动生成 CMake 缓存。
5. 在顶部的启动项下拉框中，选择 **`LabAssetManager.exe`**。

## 3. 运行与部署

由于 Qt 是动态链接库，直接编译出来的 `.exe` 如果直接双击运行，会报错找不到各种 DLL 和插件。请务必完成以下部署步骤：

请手动从 Qt 安装目录复制以下内容到  **`LabAssetManager.exe` 所在的同级目录** ：

1. **核心 DLL** ：去 `D:\AppGallery\Qt\6.0.1\msvc2019_64\bin` 下，复制 `Qt6Cored.dll`, `Qt6Widgetsd.dll`, `Qt6Sqld.dll`, `Qt6Guid.dll`。
   1. **DLL 版本冲突** ：如果有人本地是 Qt 6.5，他编译的 `.exe` 需要 `Qt6Cored.dll`，但拿给用 Qt 6.0 的同学运行，就会因为 DLL 版本不对报错。 **解决办法** ：所有测试，最终都以“集成者”电脑上编译出的版本为准。
2. **平台插件（防止报错 no Qt platform plugin）** ：去 `...\plugins\` 下，复制整个 `platforms` 文件夹。
3. **数据库驱动（防止报错 QSQLITE driver not loaded）** ：去 `...\plugins\sqldrivers\` 下，复制 `qsqlited.dll`。在 exe 目录下新建一个名为 `sqldrivers` 的文件夹，把它放进去。

### ⚠️ 关于中文乱码

如果控制台打印中文变成 `???`，或者编译报错 `C2001 常量中有换行符`，请确保所有包含中文的 `.cpp` 和 `.h` 文件是 **“UTF-8 带签名 (BOM)”** 格式。  
*解决办法：用 Windows 记事本打开该文件 -> 另存为 -> 底部编码选择“UTF-8 带签名” -> 覆盖保存。*

## 4. 团队协作规范

1. **模块解耦** ：`module_*` 之间**禁止**互相 `#include` 对方的头文件。需要通信时，通过 `app/mainwindow` 使用 Qt 的 **信号槽 (Signal & Slot)** 进行中转。
2. **数据库本地化** ：所有的 `.db` 数据库文件已被 `.gitignore` 排除。每次拉取代码后，程序首次运行会自动在 `C:\Users\用户名\AppData\Roaming\LabAssetManager` 下建库，大家各自测试， **不要把数据库文件提交到 Git** 。
3. **统一状态词汇** ：数据库中的状态统一使用英文：`available`(在用), `borrowed`(借出), `pending_repair`(待维修), `repairing`(维修), `under_maintenance`(维保), `scrapped`(报废)。界面显示时通过 `enums.h` 转换。
4. **Git 提交规范** ：

- 每次提交前先 `Pull` 远程代码。
- Commit 信息尽量清晰，如：`feat(borrow): 完成借出登记功能` 或 `fix(ui): 修复中文乱码问题`。
- **不要提交用户配置文件** ：如果在 VS 里改了 CMake 路径，VS 可能会生成 `CMakeUserPresets.json` 或 `CMakeSettings.json`，这两个文件已经在 `.gitignore` 里了， **千万别强行提交** ，否则会把别人的环境搞崩。
