# LabAssetManager (实验室设备资产管理系统)

基于 C++ (Qt6) 开发的实验室设备资产管理平台。核心业务页面已完成初步整合，目前已实现设备信息录入、编辑、删除和检索，设备借用与归还登记，维修保养台账，状态统计卡片，以及按数据表导出 CSV。

> **项目状态快照（2026-10-25）**：主窗口已接入设备、借还、维保、统计与导出四个页面，主要业务链路已经成形；设备状态已统一由 `common/enums.h` 管理，三个业务页支持导出当前检索结果，统计页中部状态明细已补齐。图表、跨模块自动刷新和自动化测试仍需继续完善。
>
> 功能依据：[docs/LabAssetManager_plan.md](docs/LabAssetManager_plan.md)。

## 🧭 项目框架

工程采用“公共基础设施 + 垂直业务模块 + 应用集成层”的结构：

```text
LabAssetManager/
├── common/               # SQLite 连接、建表与公共数据结构
├── module_equipment/     # 设备实体、数据访问、管理页与编辑对话框
├── module_borrow/        # 借还查询页、借出对话框与归还对话框
├── module_maintenance/   # 维保台账、维保对话框与数据访问
├── module_export/        # 状态卡片、数据表导出与通用 CsvExporter
├── app/                  # 主程序入口、QMainWindow 与页面导航
├── docs/                 # 计划、Schema、模块及结构说明
└── tests/                # 预留测试目录
```

| 层级/模块              | 当前职责                                                               | 实现情况                                           |
| ---------------------- | ---------------------------------------------------------------------- | -------------------------------------------------- |
| `common`             | `DatabaseManager` 单例负责连接数据库、开启外键、创建三张表和基础索引 | 已完成，可自动在用户数据目录建库                   |
| `module_equipment`   | 设备列表、排序、关键字/状态筛选、新增、编辑、删除及编号唯一性校验      | 主流程和当前结果导出完成                           |
| `module_borrow`      | 按借用人/设备、日期、借还状态查询；借出和归还均使用事务联动设备状态    | 主流程和当前结果导出完成；损坏归还映射待维修       |
| `module_maintenance` | 按设备筛选维保台账，新增/编辑记录，新增时事务联动设备状态              | 主流程和当前结果导出完成；维修完成流程未闭环       |
| `module_export`      | 六类设备状态卡片、状态明细、三张表 CSV 导出、通用 `CsvExporter`      | 状态统计完整；图表、全量字段和导出健壮性待完善     |
| `app`                | 页面导航、页面刷新和数据库初始化                                       | 四页已接入；`dataChanged` 尚未统一转发           |

当前实现基本遵守模块独立编译约定，但公共数据模型尚未完全集中到 `common`：`Equipment` 位于设备模块，`BorrowRecord` 没有独立公共结构，借还页和导出页存在直接 SQL。后续可逐步统一数据模型与访问边界。

## 🔧 改进方向

### 1. 完善导出能力

- 抽取统一的“导出当前结果”入口，直接复用各页面当前模型或查询结果；三页都应提供按钮、空结果提示、默认文件名和成功/失败反馈。
- 补齐全量字段。当前设备导出缺少品牌、购置日期、价格、责任人、备注；借还导出缺少资产编号、预计归还时间、备注；维保导出缺少资产编号、经办人。状态和类型也建议导出为中文可读文本。
- 增加“一键导出全量资产清单”或批量导出三个表的能力，明确单表导出和全量导出的区别。
- 修正 `CsvExporter` 的 CSV 兼容性：当前注释称写入 BOM，实际使用系统编码且未显式写 BOM；应统一使用 UTF-8 BOM，按 CSV 规则处理表头/逗号/引号/换行，避免行尾多余逗号，并检查写入错误。
- 导出前校验 SQL 查询错误、目标扩展名和覆盖行为，避免空模型或查询失败仍提示成功。

### 2. 补全业务状态流转

- 维保目前只能进入待维修、维修中或保养中，没有“维修完成恢复在用”“维修失败转报废”等操作。建议在维保页增加明确的完成/报废动作，并在事务中同步台账与设备状态。
- 设备编辑对话框允许直接选择任意状态，可能绕过借还和维保流程造成数据不一致。建议状态由业务动作驱动，普通编辑只修改基础信息，或对状态修改增加流程校验。
- 借还页可增加超期未归还提示、实际归还时间校验反馈和更清晰的空状态；归还损坏后应直接进入可维修流程。

### 3. 统一架构与数据访问

- 将设备、借还、维保的数据结构和状态映射收敛到 `common`，减少各页面重复 SQL 和状态文本判断。
- 为各模块补 repository/服务接口，让 UI 只处理交互，事务和业务规则集中在数据访问层。
- 将导出工具保持为与页面无关的公共能力，避免业务模块为了导出而互相包含页面头文件。

### 4. 加固数据库与构建

- 为 `equipment.status`、`borrow_record.status`、`maintenance_record.type` 增加 `CHECK` 约束，并为借出时间、维保日期补充适合检索的索引。
- 引入显式 Schema 版本和迁移机制；当前只有 `CREATE TABLE IF NOT EXISTS`，后续字段变化无法自动升级已有本地数据库。
- CMake 中的 Qt 路径和 DLL 复制路径目前是个人绝对路径。建议使用本地 CMake Preset/环境变量，并在部署阶段调用 `windeployqt`，避免换机器后构建或运行失败。
- `test_main.cpp` 同时被加入 `module_export` 库和 `TestExport` 可执行目标，建议只保留在测试目标中。

### 5. 补齐自动化测试与界面打磨

- 将 `tests/` 建成可运行的测试目标，至少覆盖数据库初始化、重复资产编号、借出/归还事务、损坏归还、维保状态联动、筛选结果和 CSV 转义。

## 👨‍💻 1. 开发环境要求（基准环境与兼容策略）

由于大家本地的机器配置不同，我们**不强求环境的绝对统一**，但为了确保代码能互相拉取编译、链接不报错，请所有人遵守以下**基准与兼容策略**：

### 📌 基准环境（用于最终测试与验收）

- **操作系统**：Windows 10 / 11 (64-bit)
- **IDE**：Visual Studio 2022
- **构建工具**：CMake (>= 3.16)
- **Qt 版本**：**Qt 6.0.1** (msvc2019_64 套件)

### 🤝 环境不一致的妥协方案（务必遵守）

1. **必须使用 MSVC 编译器**：无论你装的是 VS2017、2019 还是 2022，Qt 必须使用 **MSVC 版本**（如 `msvc2017_64`、`msvc2019_64`），**绝对禁止**有人使用 MinGW 版本（会导致无法链接）。
2. **Qt 版本“就低不就高”**：如果组内 Qt 版本有差异（比如 6.0、6.2、6.5），写代码时**只能使用低版本也支持的 API**。如果你用了高版本的特有 API，导致队友编译报错，你需要负责重写。
3. **工具集“向下兼容”**：如果有人使用 VS2022 (v143)，有人用 VS2019 (v142)，VS2022 的工具集是向下兼容的。遇到链接错误时，由使用**最新版本 VS 的同学负责最终的集成链接**。
4. **各扫门前雪（CMake 路径配置）**：每个人在自己本地的 CMake 配置中设置自己的 Qt 路径。拉取代码后，如提示找不到 Qt，请自行修改本地的 `CMAKE_PREFIX_PATH`（不要把个人的绝对路径提交到 Git 的 `CMakeLists.txt` 中）。

> **💡 强烈建议**：如果你实在搞不定自己本地的环境（比如一直报 DLL 找不到、报错 LNK2038），请在群里求助，或者使用远程桌面借用队友的电脑跑一遍。

## 🛠️ 2. 如何构建项目

1. 克隆本仓库到本地。
2. 打开 Visual Studio，选择 **“打开本地文件夹”**，选中项目根目录。
3. 在 VS 顶部的配置下拉框中，选择 **`x64-Debug`**。
4. 等待 VS 自动生成 CMake 缓存。
5. 在顶部的启动项下拉框中，选择 **`LabAssetManager.exe`**。

## 3. 运行与部署

由于 Qt 是动态链接库，直接编译出来的 `.exe` 如果直接双击运行，会报错找不到各种 DLL 和插件。请务必完成以下部署步骤：

请手动从 Qt 安装目录复制以下内容到  **`LabAssetManager.exe` 所在的同级目录** ：

1. **核心 DLL** ：去 `D:\AppGallery\Qt\6.0.1\msvc2019_64\bin` 下，复制 `Qt6Cored.dll`, `Qt6Widgetsd.dll`, `Qt6Sqld.dll`, `Qt6Guid.dll`。
   1. **DLL 版本冲突** ：如果有人本地是 Qt 6.5，他编译的 `.exe` 需要 `Qt6Cored.dll`，但拿给用 Qt 6.0 的同学运行，就会因为 DLL 版本不对报错。 **解决办法** ：所有测试，最终都以“集成者”电脑上编译出的版本为准。
2. **平台插件（防止报错 no Qt platform plugin）** ：去 `...\plugins\` 下，复制整个 `platforms` 文件夹。
3. **数据库驱动（防止报错 QSQLITE driver not loaded）** ：去 `...\plugins\sqldrivers\` 下，复制 `qsqlited.dll`。在 exe 目录下新建一个名为 `sqldrivers` 的文件夹，把它放进去。

### ⚠️ 关于中文乱码

如果控制台打印中文变成 `???`，或者编译报错 `C2001 常量中有换行符`，请确保所有包含中文的 `.cpp` 和 `.h` 文件是 **“UTF-8 带签名 (BOM)”** 格式。

*解决办法：用 Windows 记事本打开该文件 -> 另存为 -> 底部编码选择“UTF-8 带签名” -> 覆盖保存。*

## 4. 团队协作规范

1. **模块解耦** ：`module_*` 之间**禁止**互相 `#include` 对方的头文件。需要通信时，通过 `app/mainwindow` 使用 Qt 的 **信号槽 (Signal & Slot)** 进行中转。
2. **数据库本地化** ：所有的 `.db` 数据库文件已被 `.gitignore` 排除。每次拉取代码后，程序首次运行会自动在 `C:\Users\用户名\AppData\Roaming\LabAssetManager` 下建库，大家各自测试， **不要把数据库文件提交到 Git** 。
3. **统一状态词汇** ：数据库中的状态统一使用英文：`available`(在用), `borrowed`(借出), `pending_repair`(待维修), `repairing`(维修中), `maintaining`(保养中), `scrapped`(报废)。界面显示时通过 `enums.h` 转换。
4. **Git 提交规范** ：

- 每次提交前先 `Pull` 远程代码。
- Commit 信息尽量清晰，如：`feat(borrow): 完成借出登记功能` 或 `fix(ui): 修复中文乱码问题`。
- **不要提交用户配置文件** ：如果在 VS 里改了 CMake 路径，VS 可能会生成 `CMakeUserPresets.json` 或 `CMakeSettings.json`，这两个文件已经在 `.gitignore` 里了， **千万别强行提交** ，否则会把别人的环境搞崩。
