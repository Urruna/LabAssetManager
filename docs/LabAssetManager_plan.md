# 实验室设备资产管理系统

> 功能描述：基于Qt开发实验室设备资产管理平台。实现设备信息录入、编辑、删除、检索；设备借用、归还登记；设备维保记录管理；设备状态统计（在用/维修/报废）；支持导出资产清单。

## 项目框架

### 数据库

> 记录：设备信息/设备借还记录/设备维护记录

1. equipment
2. borrow_record
3. maintenance_record

### 头文件

1. `Equipment`
2. `BorrowRecord`
3. `MaintenanceRecord`
4. `DatabaseManager`

| 层                   | 职责                             | 技术要点                                                        |
| -------------------- | -------------------------------- | --------------------------------------------------------------- |
| **表示层**     | 界面展示与用户交互               | `QWidget`/`QMainWindow`、`QTableView`、`QStackedWidget` |
| **业务逻辑层** | 设备、借还、维保、统计的核心规则 | 自定义 C++ 类，不直接操作 UI                                    |
| **数据访问层** | 数据库连接、CRUD、事务           | `QSqlDatabase`、`QSqlQuery`、`QSqlTableModel`             |

## 流程

### 1 - 搭建框架

> 目标：编译通过，运行后能看到完整界面框架，点击导航能切换到空白页。

架构搭建者：集中完成项目骨架，确保主窗口能启动、数据库能连接、导航能切换，但各功能页只放占位控件。

* 用 CMake 组织工程？（CMake更灵活，qmake适合小项目）
* 实现 `DatabaseManager` 单例，完成 `QSqlDatabase::addDatabase("QSQLITE")` 和建表逻辑
* 搭建 `QMainWindow` + 左侧导航（或 Tab 页），把“设备管理 / 借还登记 / 维保记录 / 统计报表”四个页面接入
* 主窗口通过**信号**向外广播导航事件，各页面模块各自连接

### 2 - 并行开发

4个人进行各自的垂直模块开发

独立开发、独立编译，通过信号槽与主窗口通信，尽量不直接依赖他人的类实现。

这一阶段的核心纪律是： **只依赖头文件，不依赖实现** 。每个人的代码必须能在其他人模块尚未完成时独立编译通过。

### 3 - 合并&Debug

* 各模块合入 `main` 分支，解决编译冲突和接口不一致
* 统一异常处理

### 4 - 统计、导出与打磨

* 设备状态统计（在用/维修/报废数量与占比），可用 `QChart` 或简单的柱状图/饼图
* 导出资产清单：生成 CSV 或 Excel（CSV 实现成本最低，若需要 `.xlsx` 可引入 `QXlsx` 等轻量库）
* 补充用户操作反馈（状态栏提示、确认对话框、输入校验）
* 撰写项目文档（需求、设计、分工与工作量说明）

## 分工

### 设备管理模块 (module_equipment)-70

#### 功能列表：

1. **数据展示**：用 QTableView 展示设备列表，支持按列排序。
2. **多维检索**：通过资产编号、设备名称模糊搜索；通过状态下拉框精准过滤。
3. **录入设备**：弹窗填写表单。核心校验：资产编号必须唯一，不能为空；价格必须是合法数字。
4. **编辑设备**：选中某行，修改其基础信息（型号、位置、责任人等）。
5. **删除设备**：选中某行进行物理删除。

#### ⚠️ 核心业务逻辑（防坑）：

删除限制：因为数据库设了外键限制（ON DELETE RESTRICT），如果该设备还有未归还的借还记录，或者正在维修，数据库会报错，你必须捕获这个错误并在界面上弹窗提示：“该设备存在关联记录，无法删除”。

### 借还登记模块 (module_borrow) -my

#### 功能列表：

1. **借出登记**：选择一台“在用”的设备，填写借用人、借出时间、预计归还时间。
2. **归还登记**：选择一条“借出中”的记录，填写实际归还时间。
3. **历史记录查询**：按借用人、时间段、设备名查询历史流水。

#### ⚠️ 核心业务逻辑（跨表联动）：

1. **借出时**：不仅要往 borrow_record 表插一条记录，必须同时把 equipment 表里这台设备的状态改为 borrowed（借出）。这两个动作必须在同一个数据库事务（Transaction）里，要么全成功，要么全失败。
2. **归还时**：填写归还时间，同时把设备状态改回 available（在用）。如果归还时用户勾选了“设备已损坏”，状态改为 pending_repair（待维修）。

### 维保记录模块 (module_maintenance) -xx

#### 功能列表：

1. **新增维保**：选择一台设备，记录维保日期、类型（保养/维修）、费用、故障描述。
2. **维保台账**：表格展示所有设备的维保历史。

#### ⚠️ 核心业务逻辑（跨表联动）：

1. 当录入一条“维修”记录时，意味着设备坏了一段时间。此时应该把 equipment 表里的对应设备状态改为 repairing（维修中）。
2. 如果维保完成后，设备修不好了，可以直接把设备状态更新为 scrapped（报废）。

### 统计与导出模块 (module_export) -00

#### 功能列表：

1. **状态统计**：读取 equipment 表，用 SELECT status, COUNT(*) FROM equipment GROUP BY status。将结果用卡片（大字号数字）或者图表（柱状图）展示出来。
2. **资产导出**：ABC点击导出按钮，生成 CSV 格式的资产清单。

#### ⚠️ 核心业务逻辑：

**导出功能只写底层工具，不写任何具体界面。** 他需要写一个通用的 `CsvExporter` 类，提供静态函数，接收一个数据模型（Model），把它保存为 CSV 文件。

### 模块间通信

1. **设备状态变了，表格要刷新** ：B 同学在借还页把设备借出去了。B 页面发出一个信号 `emit dataChanged();`。主窗口收到后，调用 A 的 `EquipmentPage::refreshData()` 和 C 的统计页的刷新函数。这样你切回设备管理页时，状态就已经是“借出”了。
2. **跨模块传参** ：如果 B 同学在借还页面点击“借出”，弹出一个选择设备的列表，这个列表的数据其实就是 A 同学管理的数据。为了避免直接依赖，主窗口可以提供一个全局的数据访问接口，或者让 B 自己去调用 `DatabaseManager` 去查。
2. **严禁任何页面去 `#include` 另一个页面的头文件。**

### 每个模块的页面独自开发

1. **必须继承 `QWidget`** ：他们设计的页面，根类必须是 `QWidget`（不能是 `QMainWindow` ，`QMainWindow`在汇总的人手上，他来调用`QWidget` ）。

   1. 例如：在自己的 `module_borrow` 文件夹里，右键新建 `BorrowPage`（继承 `QWidget`）。他自己双击 `.ui` 文件，拖拽搜索框、表格、按钮，自己写 SQL 逻辑。在本地运行测试没问题后，提交并 Push 到 Git。
2. **必须包含特定的“公共槽函数”** ：每个模块必须公开一个刷新函数，比如 `void refreshData();`。当你在主界面或者其他模块操作后，你可以调用这个接口让他们刷新数据。
3. **文件命名规范** ：比如 B 同学负责借还，那他的类名就叫 `BorrowPage`，头文件必须叫 `borrowpage.h`，UI 文件叫 `borrowpage.ui`。（还有个.cpp文件）
4. **名字规范** ：`btn_search`, `edit_keyword`, `tableView`，不用默认的 `pushButton_1`

   1. **按钮** ：`btn_` 开头。如 `btn_search`（搜索）、`btn_add`（新增）、`btn_export`（导出）。
   2. **输入框** ：`edit_` 或 `lineEdit_` 开头。如 `edit_keyword`（搜索框）。
   3. **表格** ：统一叫 `tableView`（因为一个页面基本只有一个核心表格）。
   4. **下拉框** ：`combo_` 开头。如 `combo_status`。
   5. **标签** ：`label_` 开头。如 `label_count`（显示数量的标签）。
5. **必须打布局** ：最外层必须垂直布局，不用用绝对坐标，表格能随窗口拉伸

   1. 页面最外层必须是一个全局布局（通常是垂直布局）。
   2. 严禁手动修改控件的 `geometry` 属性。
   3. 表格（`QTableView`）的水平策略（`Horizontal Policy`）必须设为 `Expanding`，确保拉伸窗口时，表格能自动填满空白区域，而不是留出一大块黑边。
   4. 按钮高度固定（`Fixed`），不要随窗口放大而变成巨大的方块。
6. **样式**：

   1. **字体** ：所有人必须选中自己的根 `QWidget`，将 `font` 设为  **“微软雅黑”，大小 10** 。
   2. **表格（TableView）三大件** ：必须勾选 `alternatingRowColors`（隔行变色）；必须设置 `selectionBehavior` 为 `SelectRows`（选中整行）；必须在代码里隐藏左侧的行号 `verticalHeader()->setVisible(false)`。
   3. **边距（Margin）** ：页面最外层的布局，必须设置 `layoutLeftMargin`、`layoutTopMargin` 等为  **10** ，不要让控件贴着窗口边缘，显得极其压抑。

#### 参考布局

> 设计各自的 `.ui` 时， **不要乱摆放** 。统一采用 **『顶部工具栏（检索/新增） + 中间占满区域的 QTableView 表格 + 底部状态栏』** 的布局。
> 新增、编辑、借出、归还等复杂操作， **一律用 QDialog 弹窗实现** ，主页面只用来做展示和快捷搜索！

1. **设备管理页-70**
   1. **顶层：操作与检索区（水平布局）**

      1. 左边：`QLineEdit`（输入框，提示“搜资产编号/名称”） + `QComboBox`（状态下拉框） + `QPushButton`（“🔍 搜索”）。
      2. 中间：放一个 `Horizontal Spacer` 弹簧，把左右顶开。
      3. 右边：`QPushButton`（“➕ 新增”） + `QPushButton`（“📥 导出”）。
   2. **中层：核心数据区**

      1. 放一个 `QTableView`，占据整个页面  **70% 以上的面积** 。数据直观呈现。
      2. **底层：状态栏区（水平布局）**
      3. 一个 `QLabel` 显示：“共找到 120 台设备”。
   3. **弹窗设计（QDialog）** ：点击“新增”或双击某一行“编辑”时，**不要**在当前页面弹出一个巨大的输入框。而是弹出一个 `QDialog`（模态对话框），里面放表单（设备名称、型号、价格等），填完点“保存”，弹窗关闭，表格自动刷新。这叫“主从结构”。
2. **借还登记页-my**
   1. **顶层：操作区**
      1. 左边：`QComboBox`（“全部记录 / 未归还记录”） + `QDateEdit`（时间选择，看某段时间的流水）。
      2. 右边：两个醒目的按钮：“📤 登记借出”（绿色） + “📥 登记归还”（蓝色）。
   2. **中层：流水表格**
      1. `QTableView`。列名设计好：借用人、设备名、借出时间、预计归还时间、状态（借出中/已还）、经办人。
      2. **底层：空或只放统计标签** 。
   3. **弹窗设计** ：点击“登记借出”时，弹出一个 `QDialog`，里面有一个下拉框选择“可用设备”，输入“借用人”，点击“确定”。归还同理。
3. **维保记录页-xx**
   1. **顶层** ：`QComboBox`（“全部 / 维修 / 保养”） + 按钮“🛠 登记维保”。
   2. **中层** ：`QTableView`。列名：设备名、维保日期、类型、费用、经办人、故障描述。
   3. （可选）如果需要展示某个设备的维保详情，可以利用 Qt 的 `QSplitter`（分割器）或者上下布局。
4. **统计与导出页-00-主界面**
   1. **顶层：数据卡片区（水平布局）**
      1. 不要只写一行字，做一个好看的卡片。用四个 `QFrame` 横向排列，里面各放一个 `QLabel`。比如：“在用设备：130”，“维修中：5”，“已报废：12”，“外借中：8”。数字用超大字体（比如 24pt），显得非常专业。
   2. **中层：图表或明细**
      1. 如果有 `Qt Charts`，放个饼图/柱状图；如果没有，放一个 `QTableView` 列出各状态的占比。
   3. **底层：导出操作区**
      1. 放一个单独的大按钮：“📥 一键导出全量资产清单 (CSV)”。

### 注意事项

**第一，先合头文件，再合实现。** 每个人的模块对外暴露的 `.h` 文件在阶段 0 冻结后，变更必须通知全员。头文件是 4 个人之间的“合同”。

**第二，每个人的模块必须能独立编译。** 不要让“B 的代码依赖 A 还没写的 `.cpp`”导致编译失败。通过前向声明、接口抽象和信号槽，做到 A 的模块缺失时 B 仍能构建（只是运行时功能不可用）。

**第三，每天同步一次数据库 Schema。** 如果某人在开发中发现字段不够需要加列，当天在群里说明并更新 `schema.sql`，其他人拉取后重建本地数据库。避免各人本地表结构不一致导致的隐蔽 bug。

### 三、必须修复的问题

#### P0-1：损坏设备写入未定义状态

**复现步骤**

1. 借出一台设备。
2. 登记归还并勾选“设备已损坏”。
3. 查询设备表或切回设备管理页。

**实际结果**

- 数据库中的 `equipment.status` 为 `damaged`。
- 设备管理表格原样显示英文 `damaged`。
- 状态筛选没有 `damaged` 选项。
- 统计页按已知六类状态判断，因此该设备不会显示在卡片或明细行中，但仍会计入“总计”。

**修复要求**

必须统一业务决策，二选一：

- 推荐方案：损坏归还后改为 `pending_repair`，并把损坏情况写入借还备注或新增明确的损坏字段。
- 备选方案：正式增加 `damaged` 状态，同时更新 `equipmentStatusValues()`、中文映射、筛选、统计卡片、统计明细、Schema/迁移和所有相关文档。

无论选择哪个方案，都应在数据库层增加状态约束，避免类似枚举外值被静默写入。

#### P0-2：统计明细与卡片、总计不一致

**复现步骤**

1. 构造 `available`、`pending_repair`、`maintaining` 状态的设备。
2. 打开“统计与导出”页。

**实际结果**

- 卡片能够显示待维修和保养中数量。
- 中部表格没有待维修、保养中行，也没有非预设状态行。
- 总计为 4，但表格只有 1 台设备能在明细行中体现；百分比分别为 25%、0%、0%、0%，最终却显示总计 100%。

**修复要求**

- 明细表必须覆盖全部状态，并至少显示待维修、维修中、保养中、已报废；若保留 `damaged`，也必须显示。
- 所有明细数量之和必须等于总计，所有明细占比之和应为 100%（允许因四舍五入产生不超过 0.1% 的误差）。
- 建议直接遍历 `equipmentStatusValues()` 生成明细，避免维护两套状态列表。

### 四、其他缺陷与改进项

#### P1-1：CSV 输出约定不一致

- `csvexporter.cpp` 注释称写入 BOM，实际使用 `QStringConverter::System`，未显式写 BOM。
- 数据行末尾多一个逗号；表头未使用统一引号规则。
- 未检查流写入错误，磁盘写满或写入中断时可能仍返回成功。

建议统一采用 UTF-8 BOM，并按 CSV 规则统一处理表头、逗号、引号、换行和写入错误。

#### P1-2：全量导出字段不足

统计页的“设备总览”只导出资产编号、名称、型号、状态、位置，缺少品牌、购置日期、价格、责任人、备注；“借还表”和“维保表”同样缺少部分字段。计划中的“一键导出全量资产清单”尚未实现。建议明确“当前检索结果导出”和“全量导出”两个入口，并让导出字段可追溯、状态使用中文。

#### P1-3：维保流程未闭环

- 维保页只能让设备进入待维修、维修中或保养中，没有“维修完成恢复在用”和“维修失败转报废”的正式操作。
- 目前用户只能到设备编辑对话框中手工改状态，容易绕过台账和事务规则。
- 维保页只有设备筛选，缺少计划中提出的维修/保养类型筛选，也没有日期范围或文本检索。

#### P1-4：设备状态可绕过业务流程修改

设备新增和编辑对话框允许直接选择任意状态，保存时也会直接提交状态字段。代码检查表明这会允许用户把维修中设备改成其他值，可能与未结束的借还或维保记录冲突。应限制普通编辑只能修改基础信息，状态变化通过借出、归还、维修完成、报废等业务动作驱动。

#### P1-5：跨模块刷新信号未接通

三个业务页均声明并通过了 `dataChanged()` 信号的产生逻辑，但主窗口没有连接这些信号到设备页、借还页、维保页和统计页。当前主要依靠切换页面时主动刷新，暂时能掩盖问题；一旦增加同页联动或后台数据修改，就可能显示过期数据。

#### P2-1：界面一致性

- 借出、归还、维保对话框的按钮仍显示英文 `OK` / `Cancel`，同页面其他按钮为中文。
- 维保页由代码创建控件，未完整遵循统一的字号、边距和对象命名约定，后续自动化测试定位控件较困难。

### 五、建议补充的验收用例

1. 损坏归还后，数据库中不存在枚举外状态，设备可在维修流程中被正确处理。
2. 统计卡片、明细行和总计三者完全一致，百分比合计为 100%。
3. 设备、借还、维保三页按不同筛选条件导出后，行数和可见表格一致。
4. 全量资产导出包含 Schema 中的全部业务字段，中文状态可读。
5. 维修完成、保养完成和维修失败报废三种状态流转均有界面入口，并正确更新设备状态。
6. 借出后的设备不能在设备管理页被手工改成“在用”；存在未归还记录时不能绕过归还流程。
7. 空库、搜索无结果、重复资产编号、日期起始晚于结束、非法时间和数据库写入失败均有明确提示。
8. 使用 CTest 自动执行数据库初始化、借还事务、维保状态联动、统计聚合和 CSV 转义测试。
